# ボスの勝率の出し方(刻戦)

ボスやソロのステージの敵の勝率は、必ずこの3つの手順で出す。プレイヤーは強いパーティを選んで挑むので、ランダムなパーティの勝率だけでは決めない。

1. **ランダムなパーティでシミュレーション**:使えるキャラ(アドバンスならガチャ込み。ただしガチャの★1・★2は最初から外す)からランダムに3枚選んだパーティを、たくさん戦わせる。「適当に打つ」「考えて打つ(深さ3)」の両方を出す(全体の目安)。
2. **適正パーティの抽出**:手順1の「考えて打つ」勝率が高い順に、上位10通りのパーティを抜き出す。
3. **適正パーティだけでシミュレーション**:その10通りだけで、もう一度たくさん戦わせる(考えて打つ)。**ここで出た平均が、そのボスの勝率**。

## 道具

`tools/bossrate.js` がこの3つを順番に行う(4並列、約3〜4分)。

```
# 既存のステージ(index.html の STAGES)
node tools/bossrate.js --stage y3

# ガチャキャラ・ENEMIES・プレイヤー用キャラに倍率を掛けた敵(id:HP倍率:ATK倍率:DFS倍率:フィジカル)
node tools/bossrate.js --foes g_y3c:8:2.6:1:1.4 --level 4 --read 0.5
```

主な指定(省略時):`--parties 400`(手順1のパーティ数)、`--games 20`(手順1の1パーティあたりの試合数)、`--top 10`、`--final 300`(手順3の試合数)、`--pool all`(ガチャ込み。`basic` でガチャ抜き)、`--level 4`(CPUの深さ)、`--read 0.35`(ボスが癖を読む割合の上限)、`--seed 1`。

## いまの決まった測り方(仮で十分なとき)

- 適正パーティは `tools/parties/fixed5.json` の5通りに固定する(カジ【始】→ナガレ→カガミ / ナガレ→ゼノ【仮面】→カガミ / ゼノ【仮面】→ハヤ→ナガレ / モト→ゼノ【仮面】→カスミ / シラ→ヤジリ→ナガレ)。
- 明らかに弱いパーティは試さない。完璧な適正パーティでなくてよい(仮でよい)。
- 測るとき:`node tools/bossrate.js --foes ... --load fixed5 --final 60 --verbose`(数十秒)。合わせるとき:`--target 2` を足す。
- いらない計算は回さない。止まっている計算があれば止める。

## 効率よく測る(数値合わせ)

1. 最初に1回だけ、適正パーティを探して保存する:`node tools/bossrate.js --foes ... --save 名前`(約50秒)。手順1はHPを半分にして見分ける(`--scout 0.5`)。強すぎるボスだと誰も勝てず、強いパーティを見分けられないため。
2. 目標の勝率に合わせる:`node tools/bossrate.js --foes ... --load 名前 --target 8`。保存した10通りだけで、HPの倍率を自動で上げ下げする(1回約20秒×6回)。
3. 数値を少し変えたあとの確認は `--load 名前` だけ(約20秒)。特性や技を大きく変えたときは、適正パーティが入れ替わるので `--save` からやり直す。

## 報告のしかた

- 出力は短くまとめて出る(会話の量を節約するため)。パーティごとの勝率が必要なときだけ `--verbose` を付ける。

- 結果は日本語で、手順3の勝率を「このボスの勝率」として出す。手順1の数字(ランダムなパーティの勝率)も目安として添える。
- 適正パーティの上位(顔ぶれと勝率)も見せる。特定のキャラばかり並ぶときは、そのことも伝える。
- 数値を合わせるときは、HP・ATK・DFS・フィジカル・CPUの深さ・読みの割合のどれを動かしたかをはっきり書く。
- 試合数が少ないと数字がぶれる。目標に近いところでは `--final` を増やして確かめる。
